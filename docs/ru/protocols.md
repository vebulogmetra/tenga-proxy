# Протоколы

Tenga Proxy поддерживает широкий спектр прокси-протоколов для обеспечения совместимости с различными серверами и сервисами.

## Поддерживаемые протоколы

### VLESS

VLESS - это протокол следующего поколения, разработанный для Xray. Поддерживает:

- **Reality** - защита от DPI с использованием TLS
- **XTLS** - эффективная передача данных
- Различные транспортные протоколы (TCP, WebSocket, gRPC и др.)

### Trojan

Протокол Trojan обеспечивает высокую безопасность:

- Поддержка TLS
- Совместимость с HTTP/HTTPS
- Защита от DPI

### VMess

Протокол от V2Ray с поддержкой:

- Шифрования AES и ChaCha20
- Аутентификации через UUID
- Совместимости с V2Ray

### Shadowsocks

Поддерживаются ссылки SIP002 и legacy (вся учётная запись с адресом в base64),
а также percent-кодированные ключи Shadowsocks 2022.

- AEAD: `aes-128-gcm`, `aes-256-gcm`, `chacha20-poly1305`,
  `chacha20-ietf-poly1305`, `xchacha20-poly1305`, `xchacha20-ietf-poly1305`.
- Shadowsocks 2022: `2022-blake3-aes-128-gcm`, `2022-blake3-aes-256-gcm`,
  `2022-blake3-chacha20-poly1305`. Ключи проверяются на длину при импорте.
- Потоковые шифры, `none`, `plain` и плагины SIP003 не поддерживаются.

### Hysteria2

Поддерживается Hysteria2 (`hysteria2://` и `hy2://`) с TLS, обфускацией
salamander и параметрами `fm` (finalmask).

- Port hopping: несколько портов или диапазон в адресе, например
  `server:443,20000-50000`, либо параметр `mport=20000-50000`.
- Интервал: `hop-interval=30` (также `hopInterval`), число или диапазон в
  секундах, минимум 5; по умолчанию 30 секунд.
- Brutal: `upmbps` включает алгоритм и задаёт скорость отправки в Мбит/с;
  `downmbps` задаёт скорость приёма. Явные настройки из `fm` сохраняются.

### SOCKS

Поддержка стандартных SOCKS-протоколов:

- **SOCKS4** - базовая версия
- **SOCKS4a** - с поддержкой DNS
- **SOCKS5** - полная версия с аутентификацией

### HTTP/HTTPS

Поддержка HTTP-прокси:

- HTTP прокси с аутентификацией
- HTTPS прокси
- Совместимость с веб-браузерами

## Форматы ссылок

### VLESS

```
vless://UUID@server:port?encryption=none&security=tls&alpn=http/1.1#Name
```

### Trojan

```
trojan://password@server:port#Name
```

### VMess

```
vmess://base64_encoded_json_config
```

### Shadowsocks

```
ss://base64(method:password)@server:port#Name
```

### SOCKS

```
socks://server:port#Name
```

## Транспортные протоколы

### TCP

Стандартный TCP-транспорт с поддержкой HTTP-обфускации.

### WebSocket

WebSocket-транспорт для обхода блокировок:

- Поддержка TLS
- Настройка пути (path)
- Совместимость с CDN

### gRPC

gRPC-транспорт для высокой производительности:

- Поддержка мультиплексирования
- Эффективное использование соединений
- Совместимость с HTTP/2

### HTTP/2

Отдельный транспорт `h2` удалён из xray-core и не поддерживается.
HTTP/2 в gRPC и XHTTP продолжает работать. Для WebSocket и HTTP Upgrade
при сборке конфига из ALPN исключаются `h2` и `h3`; исходная ссылка сохраняется.

## Настройка протоколов

Каждый протокол может быть настроен с различными параметрами:

- **Безопасность** - TLS, REALITY, none
- **Шифрование** - различные алгоритмы
- **Транспорт** - TCP, WebSocket, gRPC и др.
- **Дополнительные параметры** - SNI, ALPN, и т.д.

Параметр `allowInsecure` не действует: ядро не принимает его. Проверка
сертификата TLS остаётся включённой.

## Обход блокировок

В «Настройки» → «Обход блокировок» доступны фрагментация TLS и mux.
Настройки используются при подключении и замере задержки. При сохранении
настроек активное подключение перезапускается с новым конфигом.
Оба переключателя по умолчанию выключены.

Фрагментация действует на профили с TLS или REALITY, кроме Hysteria2 и
профилей со своими TCP-масками. По умолчанию режется ClientHello (`tlshello`),
размер фрагмента — `100-200` байт, пауза — `10-20` мс. Можно указать номера
пакетов (`1-3`), размер и паузу числом или диапазоном. Неверные значения
заменяются значениями по умолчанию. Эффективность требует проверки в своей сети.

Mux объединяет потоки в одном соединении для VLESS и Trojan, кроме XHTTP,
SplitHTTP и VLESS Vision. UDP на порту 443 идёт обычным путём, минуя mux.
