# Установка

## Переход с Tenga Proxy

Приложение переименовано в Veblock. Обновление ставится поверх прежней версии:
профили, подписки и настройки сохраняются. Команда запуска (`tenga-proxy`),
имя deb-пакета и каталог настроек (`~/.config/tenga-proxy`) прежние. На
Windows установщик заменяет ярлыки «Tenga Proxy» на «Veblock»; имя службы
(`TengaProxySvc`) и каталог установки остаются прежними.

## Linux: deb-пакет

Скачайте `tenga-proxy_<версия>_amd64.deb` со страницы
[Releases](https://github.com/vebulogmetra/tenga-proxy/releases) и установите:

```bash
sudo apt install ./tenga-proxy_<версия>_amd64.deb
```

apt сам поставит зависимости: Python 3.11+, PyGObject, GTK 4, libadwaita 1.5+
и requests. Подходят Ubuntu 24.04, Debian 13 и новее; на более старых
дистрибутивах libadwaita 1.5 нет, и apt откажется ставить пакет.

### Где что лежит

| Что | Где |
|---|---|
| Приложение | `/usr/lib/tenga-proxy` |
| Команда запуска | `/usr/bin/tenga-proxy` |
| xray-core и геобазы | `/usr/lib/tenga-proxy/core/bin` |
| Помощник маршрутов TUN | `/usr/libexec/tenga-proxy/tun-route-helper` |
| Правило sudoers | `/etc/sudoers.d/tenga-proxy` |
| Настройки, профили, логи | `~/.config/tenga-proxy` |

### Режим TUN

При установке пакет выдаёт xray-core права `cap_net_admin,cap_net_raw`:
TUN-интерфейс ядро создаёт само. Маршрут по умолчанию переключает помощник
через `sudo` без пароля; правило пакета разрешает его группе `sudo`, то есть
администраторам системы. Пользователю не из этой группы TUN недоступен, пока его
не добавят (`sudo usermod -aG sudo <имя>` и повторный вход). Чего не хватает,
показывают настройки и ошибка подключения.

### Переход с AppImage

AppImage больше не выпускается. При установке пакет удаляет помощник
`/usr/local/libexec/tenga-proxy` и правила `/etc/sudoers.d/tenga-proxy-tun-helper-*`,
а приложение при первом запуске — ярлык `~/.local/share/applications/tenga-proxy.desktop`,
если он запускал AppImage, и его значки. Настройки в `~/.config/tenga-proxy`
остаются. Сам файл `~/.local/bin/tenga-proxy.AppImage` и копию ядра
`~/.config/tenga-proxy/bin` удалите вручную.

### Удаление

```bash
sudo apt remove tenga-proxy   # purge удалит и правило sudoers
```

Настройки в `~/.config/tenga-proxy` остаются — удалите каталог вручную, если
они не нужны.

## Сборка deb-пакета

### Требования для сборки

- Системные зависимости (устанавливаются через `python cli.py setup-dev`)
- Бинарник `xray` и геобазы в `core/bin/`
- `dpkg-deb` (есть в любой системе на Debian/Ubuntu)

### Сборка и установка

```bash
python cli.py build               # dist/tenga-proxy_<версия>_<arch>.deb
python cli.py install             # sudo apt install этого файла
python cli.py setup               # то же одной командой
python cli.py install --uninstall # sudo apt remove tenga-proxy
```

### Ссылки импорта и обновления

Desktop-файл регистрирует `veblock://` и `wingeon://` и передаёт
URI аргументом `%U`, без shell-интерпретации. Повторный экземпляр передаёт открытие
URI работающему приложению через GApplication.

Приложение уведомляет о релизах desktop-репозитория и открывает проверенную
HTTPS-страницу GitHub. Установка обновлений из интерфейса не включена: сначала нужны
подписанный манифест, доверенный публичный ключ и процесс ротации ключей. Скачивание,
замена и автоматический запуск нового исполняемого файла при проверке версии
не выполняются. Обновляйте приложение обычным способом установки.

Stats API ядра использует Unix-сокет в новом приватном каталоге с правами 0700
на каждый запуск. Отдельный TCP-порт статистики больше не открывается; способ
поддерживается комплектным xray 26.9.9. Статистика остаётся внутренней функцией
приложения, а не публичным API.

## Windows

### Установка

Скачайте `veblock-<версия>-windows-x64-setup.exe` со страницы
[Releases](https://github.com/vebulogmetra/tenga-proxy/releases) и запустите.
Нужны Windows 10 или 11 (x64); установщик попросит права администратора (UAC).
В мастере можно включить ярлык на рабочем столе и запуск при входе в систему.

Библиотеки Qt, xray-core и драйвер wintun входят в установщик, отдельно
ничего ставить не нужно.

Автозапуск и ссылки `veblock://`, `wingeon://` записываются в реестр
(`HKCU`) того пользователя, от имени которого выполнена установка.

### Где что лежит

| Что | Где |
|---|---|
| Приложение | `C:\Program Files\Veblock` (после обновления с Tenga Proxy — прежний `C:\Program Files\Tenga Proxy`) |
| Настройки и профили | `%APPDATA%\tenga-proxy` |
| Логи приложения | `%LOCALAPPDATA%\tenga-proxy\logs` |
| Логи и журнал службы | `%ProgramData%\tenga-proxy` (пользователям — только чтение) |

### Режим TUN и служба «Veblock»

Создать сетевой интерфейс и поменять маршруты без прав администратора нельзя,
поэтому установщик регистрирует службу `TengaProxySvc` (отображаемое имя
«Veblock», отложенный автозапуск). Приложение передаёт ей конфигурацию
TUN по локальному каналу, и запрос UAC при подключении не появляется.
Режим системного прокси служба не использует.

Служба:

- запускает xray-core с TUN-интерфейсом `xray0`;
- направляет трафик в туннель маршрутами `0.0.0.0/1` и `128.0.0.0/1`, а адрес
  прокси-сервера — через основной интерфейс;
- пускает системный DNS через туннель правилом NRPT с комментарием
  `tenga-proxy`;
- проверяет конфигурацию: принимает только inbound'ы на loopback, поэтому в
  режиме TUN на Windows раздача прокси в локальную сеть недоступна.

Каждое изменение сети записывается в журнал и откатывается при отключении,
падении xray-core, закрытии приложения (через 15 секунд), остановке службы и
при её запуске после сбоя или перезагрузки.

Ограничения: IPv6 через туннель не идёт (как и на Linux); управлять режимом
TUN через службу может любой пользователь, вошедший в систему локально.

### Удаление

«Параметры → Приложения → Veblock → Удалить». Служба останавливается,
откатывает сеть и удаляется. Настройки в `%APPDATA%\tenga-proxy` остаются —
удалите каталог вручную, если они не нужны.
