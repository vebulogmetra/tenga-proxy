# Маршрутизация

Маршрутизация в Veblock позволяет гибко управлять направлением сетевого трафика через различные каналы подключения.

## Режимы маршрутизации

### Прокси для всего трафика (PROXY_ALL)

В этом режиме весь трафик направляется через прокси-сервер:

- Все соединения проходят через настроенный прокси
- Возможность исключения локальных сетей
- Подходит для полной анонимизации трафика

### Кастомная маршрутизация (CUSTOM)

Позволяет настраивать правила маршрутизации вручную:

- Список прямых подключений (DIRECT)
- Список подключений через VPN (VPN)
- Список подключений через прокси (PROXY)
- Возможность настройки приоритета правил

## Списки маршрутизации

### Прямые подключения (DIRECT)

Список доменов и IP-адресов, трафик к которым:

- Не проходит через прокси
- Использует прямое подключение
- Подходит для локальных ресурсов и внутренних сервисов

### Подключения через VPN (VPN)

Список доменов и IP-адресов, трафик к которым:

- Направляется через VPN-соединение
- Использует VPN-интерфейс
- Подходит для ресурсов, требующих VPN-доступа

### Подключения через прокси (PROXY)

Список доменов и IP-адресов, трафик к которым:

- Направляется через основной прокси
- Использует настроенные параметры прокси
- Подходит для анонимизации и обхода блокировок

## Форматы записей

В каждой строке списка — одна запись. Запись, которую ядро не поняло бы,
пропускается: одно негодное правило иначе сорвало бы всё подключение.

### Домены

| Запись | Что совпадает |
|---|---|
| `example.com` | домен и все его поддомены |
| `*.example.com`, `.example.com` | то же самое |
| `full:example.com` | только сам домен |
| `google` | любое имя, где встречается слово (без точки — подстрока) |
| `keyword:video` | то же, явно |
| `regexp:^ads\d+\.example\.com$` | регулярное выражение |
| `geosite:category-ru` | категория из geosite.dat |

### Адреса и сети

| Запись | Что совпадает |
|---|---|
| `192.168.1.1`, `2001:db8::1` | один адрес |
| `192.168.1.0/24`, `fc00::/7` | подсеть |
| `geoip:ru` | страна из geoip.dat |

`geoip:private` допустим только в списке «Напрямую»; для частных сетей есть
готовое правило (см. ниже).

Категория, которой нет в геобазах, пропускается с предупреждением в журнале.
Состояние баз видно в «Настройки → О программе», там же кнопка «Обновить».

## Блокировка

Список «Блокировать»: соединения обрываются, а имена не резолвятся (ответ
NXDOMAIN). Применяется раньше остальных списков при любом порядке групп.

## Готовые правила

Стоят после пользовательских списков: явная запись всегда главнее.

- **Локальные сети напрямую** — `127.0.0.0/8`, `10.0.0.0/8`, `192.168.0.0/16` и
  другие частные диапазоны. Включено по умолчанию, действует в обоих режимах.
- **Российские сайты и IP напрямую** — `geosite:category-ru`,
  `geosite:category-gov-ru`, `geoip:ru`. Выключено по умолчанию, действует в
  режиме списков. Нужны геобазы.

## DNS

Имя резолвит DNS той сети, в которую пойдёт сам трафик:

- домены списка «Напрямую» и российские сайты готового правила — DNS вашей сети;
- домены списка «Через VPN» — DNS-сервер VPN (запросы к нему идут через VPN);
- домены списка «Через прокси» и всё остальное — DNS из настроек (по умолчанию
  DoH через прокси).

Если DNS из настроек недоступен, имена провайдеру не уходят: системный
резолвер обслуживает только свои домены.

В режиме TUN запросы приложений перехватываются и обрабатываются теми же
правилами («Настройки → DNS → Перехватывать DNS приложений»). На системах с
systemd-resolved для этого нужен установленный помощник маршрутов
(`python cli.py install`); запросы типов, отличных от A и AAAA, пересылаются
DNS вашей сети без изменений.

## IPv6 в режиме TUN

В туннель заворачивается только IPv4, поэтому на время сеанса TUN исходящий IPv6
закрыт, кроме локальной сети: иначе приложения ходили бы по нему мимо прокси.
Приложения получают отказ сразу и переходят на IPv4, сайты только с IPv6 не
открываются. Закрывает его таблица nftables `inet veblock`, поэтому нужен пакет
`nftables`.

Отключение снимает таблицу. Если приложение упало, её снимет следующий запуск, а
вручную — `sudo nft delete table inet veblock`.

## Блокировка трафика при обрыве

Настройка «Блокировать трафик при обрыве» («Настройки → Режим работы», только в
режиме TUN на Linux) закрывает весь прямой трафик на время сеанса: если ядро
упадёт или смена сервера не удастся, приложения получат отказ, а не пойдут в
интернет мимо прокси.

Остаются открыты локальная сеть, сокеты самого ядра и VPN, привязанный к серверу.
Закрытие держится до «Отключить», выхода из приложения или кнопки «Снять блокировку»;
логотип в этом состоянии подключает сервер прошлого сеанса.

Ограничения:

- Нужен перехват DNS и systemd-resolved. Без перехвата подключение отказывает с
  объяснением, без resolved приложение предупредит, что DNS не защищён.
- VPN работает, только если он привязан к серверу и это плагин NetworkManager
  (например, OpenVPN). WireGuard и VPN вне настроек сервера с этой настройкой
  работать не будут.
- GNOME покажет «ограниченное подключение» при обрыве: проверка связности идёт мимо
  туннеля.
- Страница входа в сеть (captive portal) не откроется: сначала отключитесь.
- Проброшенные порты и SSH снаружи перестанут отвечать.

Если приложение упало, сеть закрыта до следующего запуска, который снимет блокировку и
сообщит об этом. Вручную: `sudo nft delete table inet veblock`.

## Приоритет правил

Порядок обработки правил маршрутизации:

1. **Более специфичные правила** - имеют более высокий приоритет
2. **Порядок в конфигурации** - правила обрабатываются в порядке определения
3. **Типы правил** - могут иметь разный приоритет в зависимости от настроек

## Настройка в GUI

### Общие правила

«Настройки → Маршрутизация»: режим, приоритет групп, готовые правила и четыре
списка. Они действуют для всех серверов, у которых нет своих правил. Если был
импорт, в группе «Дополнительно» есть строка «Маршрутизация до импорта» → «Вернуть».

Старая установка, у которой списки лежат в текстовых файлах, продолжает читать их,
пока форму на этой странице не изменили. После первой правки общие правила
сохраняются в settings.json (`routing.use_saved_lists`).

### Свои правила сервера

«VPN и маршруты…» в меню сервера, переключатель «Свои правила маршрутизации».
Выключен — сервер использует общие правила. При включении форма начинается с копии
общих правил, и дальше их правка на этот сервер не влияет. Выключение возвращает
сервер к общим правилам, его собственные списки не хранятся.

На странице мониторинга строка «Правила» показывает, что применено: «Общие» или
«Сервера».

## Примеры конфигурации

### Простой пример

```
DIRECT: 192.168.0.0/16, 10.0.0.0/8, localhost
PROXY: *.google.com, *.youtube.com
VPN: *.company.com
```

### Сложный пример

```
DIRECT: geosite:category-ru, geoip:ru, domain:local
PROXY: geosite:google, blocked.example
VPN: domain:restricted-site.com, 10.10.10.0/24
```

### Импорт и проверка правил

URL сайта в списке преобразуется в имя хоста: схема, порт, путь и query удаляются,
кириллические домены преобразуются в IDNA, IPv6 поддерживается. Credentials в URL
отклоняются. Записи `domain:`, `full:`, `regexp:`, `geosite:`, `geoip:` и CIDR
сохраняются; regexp размещайте отдельной строкой, тогда его запятые и точки
с запятой не разделяют правило. Имя в `full:` и `domain:` приводится к нижнему
регистру и в IDNA: ядро сравнивает правило с запрошенным именем именно в таком
виде, и `full:Пример.РФ` иначе не сработал бы. Регистр `regexp:` и `keyword:`
не меняется. После нормализации повторы удаляются с сохранением порядка.
Неизвестные geo-категории останавливают подключение с объяснением.

Ссылки `veblock://routing/add/…`, `wingeon://routing/add/…` и совместимый Happ-формат
до подтверждения открывают окно со строками «подпись — значение»: имя набора маршрутов
из ссылки, режим (если меняется), по каждому из списков «Через прокси», «Напрямую»
и «Блокировать» — число правил и сколько добавится и удалится, с раскрывающимся
перечнем изменений. «Было» считается по тем спискам, с которыми подключилось бы
ядро, в том числе по текстовым файлам старой установки.

Списки импорта сохраняются в settings.json (`routing.use_saved_lists`), чтобы старые
текстовые файлы не перекрыли их при подключении. Старые установки продолжают читать
файлы списков, пока не выполнен такой импорт; VPN-список из файла при импорте
сохраняется.

Строка «Остальное» говорит, что вне списков трафик идёт через прокси. Если ссылка
просит пускать остальное напрямую (`GlobalProxy=false`), строка выделена и сообщает,
что этот режим не поддерживается. DNS, VPN, порядок правил и адреса геобаз из ссылки
не импортируются — это строка «Не переносится». Импорт сам не запускает подключение.

Перед импортом прежняя маршрутизация сохраняется в settings.json (`routing_backup`,
один уровень: следующий импорт заменяет копию). Вернуть её можно кнопкой «Вернуть»
в уведомлении после импорта или в «Настройки → Маршрутизация → Дополнительно →
Маршрутизация до импорта». Старая установка после отката снова читает текстовые
файлы списков.

Импорт меняет общие правила. Серверы со своими правилами он не затрагивает.

### Набор маршрутов из подписки

Провайдер может передать набор маршрутов заголовком ответа `routing`: ссылкой
`happ://routing/add/…`, `veblock://routing/add/…` (и `onadd`) или голым base64 того
же JSON. После обновления подписки Veblock показывает то же окно, что при открытии
ссылки вручную, с первой строкой «Подписка». Ничего не применяется без кнопки
«Импортировать»: `onadd` тоже только предлагается.

Принятый или отклонённый набор повторно не предлагается, пока провайдер не пришлёт
другой (хеш запоминается в группе подписки, `sub_routing_handled`). Если окно не
показано — например, главное окно закрыто, — набор будет предложен при следующем
обновлении. Если та же подписка просит сменить адрес, сначала спрашивается адрес,
а набор маршрутов — со следующим обновлением.

`happ://routing/off` в заголовке предлагает вернуть стандартные списки «Через
прокси», «Напрямую», «Блокировать» и режим. Список «Через VPN», порядок и готовые
правила — настройки устройства, их сброс не трогает.

Если набор или сброс ничего не меняет (те же режим и списки), окно не
показывается, а набор считается обработанным. Ссылка `happ://routing/off`, открытая вручную, не поддерживается.

### Дополнительный DNS и геобазы

Добавлены пресеты [Quad9](https://docs.quad9.net/services/) и
[Comss.one](https://www.comss.ru/page.php?id=7315). Comss.one — сторонний Smart DNS,
а не режим приватности. Xbox DNS не добавлен: на момент сверки 20.10.2026
[официальный сайт](https://xbox-dns.ru/) сообщает о недоступности сервиса.

Дополнительный DNS — ещё один удалённый resolver, а не обещание строгого
последовательного failover. Старые настройки читаются без добавления второго
сервера. Сохраняются split-DNS, bootstrap имени сервера, блок-лист и DNS
NetworkManager VPN. Дополнительные удалённые серверы получают собственный тег
для маршрутизации через прокси при включённой соответствующей настройке.

Обновление геобаз фиксирует один релиз Loyalsoldier для обоих файлов и контрольных
сумм. В geo/release.json сохраняются версия и digests; откат и изменённое содержимое
уже установленной версии отклоняются. Ошибка установки восстанавливает прежние
файлы и метаданные. SHA256 из того же источника проверяет целостность, но не является
независимой подписью издателя. Встроенные базы остаются запасным вариантом при
повреждении скачанных файлов.
