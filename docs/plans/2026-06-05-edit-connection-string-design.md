# Дизайн: редактирование строки подключения профиля

Дата: 2026-06-05
Статус: одобрено

## Цель

Добавить возможность редактировать строку подключения (share link) для профиля —
как одиночного, так и входящего в группу/подписку. На вкладке «Профиль» окна
настроек профиля появляется группа «Редактировать» с полем ввода, предзаполненным
текущей ссылкой, и кнопкой «Применить».

## Контекст

Окно настроек профиля: `ProfileVpnSettingsDialog` в
`src/ui/dialogs/profile_vpn_settings.py`. Вкладка «Профиль» создаётся методом
`_create_profile_page()` и сейчас содержит группу «Профиль» с полем «Имя профиля»
и read-only полем «Ссылка» + кнопкой «Копировать».

Уже доступно и переиспользуется без изменений:
- `parse_link(link) -> ProxyBean | None` из `src.fmt.parsers`.
- `ProfileEntry.bean` — заменяемое поле; `id`, `group_id`, `vpn_settings`,
  `routing_settings` остаются при замене bean.
- `main_window._open_profile_vpn_settings` после закрытия диалога вызывает
  `profiles.save()` и `_refresh_profiles()`; колбэк `on_settings_applied`
  перезагружает конфиг xray для активного профиля.

## Решения (по итогам brainstorming)

1. **Смена протокола**: разрешена любая. Вставка ссылки другого протокола
   полностью заменяет bean, сохраняя id/группу/настройки профиля.
2. **Роль кнопки «Применить»**: «Разобрать/Превью». Кнопка валидирует и
   разбирает ссылку, заменяет bean в памяти и сразу обновляет поля «Имя» и
   read-only «Ссылка». Фактическое сохранение в хранилище — по общей кнопке
   Apply диалога (как и для остальных настроек).
3. **Поле редактирования**: `Gtk.Entry`, предзаполненное
   `bean.to_share_link()` — единообразно с остальным диалогом.

## UI

В `_create_profile_page()` после группы «Профиль» добавляется `Gtk.Frame`
«Редактировать»:
- подсказка (`<small>`, dim-label) с перечнем поддерживаемых схем;
- `self._edit_link_entry: Gtk.Entry` с текущей ссылкой;
- кнопка «Применить» (`_on_apply_link_clicked`);
- `self._edit_status_label: Gtk.Label` для ошибки разбора / «Применено».

## Логика `_on_apply_link_clicked`

1. Текст из `_edit_link_entry`, `strip()`. Пусто → статус «Введите ссылку»
   (красным), выход.
2. `bean = parse_link(link)` (локальный импорт).
3. `bean is None` → статус «Не удалось разобрать ссылку» (красным); bean профиля
   не трогаем; выход.
4. Успех:
   - `self._profile.bean = bean`;
   - `self._conn_string_entry.set_text(bean.to_share_link())`;
   - если в ссылке был задан remark (`#...`) — обновить `_profile_name_entry`
     значением `bean.display_name`; иначе имя не трогать;
   - нормализовать `_edit_link_entry` к `bean.to_share_link()`;
   - статус «Применено» (зелёным).

Имя: в `save_settings()` уже есть `self._profile.bean.name = profile_name` из
поля имени — это корректно выставляется поверх нового bean, конфликта нет.

## Объём

Изменяются два диалога редактирования профиля:

1. `src/ui/dialogs/profile_vpn_settings.py` — `ProfileVpnSettingsDialog`,
   вкладка «Профиль» (окно «Настройки VPN», двойной клик по профилю).
2. `src/ui/dialogs/edit_profile.py` — `EditProfileDialog`, отдельный диалог
   «Редактировать профиль» (кнопка «Редактировать» и контекстное меню).

В обоих добавляется группа «Редактировать» с тем же поведением. В
`EditProfileDialog` обработчик дополнительно синхронизирует поля
Имя/Сервер/Порт из нового bean, чтобы финальный `apply_changes()` (OK) их не
затёр. Модели, парсеры, хранилище не меняются.

## Тесты

`tests/test_ui_profile_edit_link.py` — покрывают чистую логику
`_apply_edited_link` обоих диалогов (замена bean, смена протокола, пустая и
невалидная ссылка, признак наличия remark). GTK-слой не покрывается
автотестами (как и весь остальной GTK-код проекта).
