# Самообновление на Windows

## Задача

Сейчас приложение раз в сутки находит новый релиз (`src/core/app_update.py`),
показывает тост и в «О программе» открывает страницу релиза в браузере. Дальше
пользователь сам скачивает и запускает установщик. На Windows приложение должно
скачать, проверить и запустить установщик само. Linux пока не меняется.

## Поведение

- Тост ежедневной проверки: «Доступна версия X» с кнопкой «Обновить»
  (действие `install-app-update`). Там, где самообновления нет, тост прежний:
  «Доступна версия X. Откройте настройки → О программе».
- «О программе»: кнопка «Обновить…» вместо «Открыть релиз». Активна, когда в
  релизе есть установщик Windows с контрольной суммой и установка не идёт.
- Подтверждение: «Будет установлена версия X. Подключение прервётся, приложение
  перезапустится».
- Загрузка с прогрессом в подписи («Загрузка… 42 %»), затем проверка размера и
  SHA-256. Загрузка идёт при живом подключении: GitHub может быть недоступен
  напрямую.
- Затем приложение штатно отключается (системный прокси, TUN через службу) и
  только потом запускает установщик с UAC. Так отключение не гонится с
  остановкой службы, которую делает сам установщик.
- Согласие в UAC — приложение запускает наблюдателя перезапуска и выходит.
  Отказ — остаётся работать (уже отключённым), подпись «Установка отменена».
- Установщик идёт с `/SILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS`:
  окно прогресса видно, вопросов нет.

## Перезапуск

Пункт `[Run]` с `runasoriginaluser` для этого не годится: он работает через
непривилегированный процесс Setup, который сам поднял права. Установщик,
запущенный через `runas` уже администратором, такого процесса не имеет, и
новая версия стартовала бы с повышенными правами (не тот HKCU и каталог
настроек при другой учётной записи, UIPI для второго экземпляра).

Поэтому перезапуск делает само приложение до выхода: скрытый `powershell.exe`
от имени пользователя ждёт, пока процесс установщика (PID из
`ShellExecuteExW`) исчезнет, и запускает `sys.executable`. `Get-Process -Id`
видит процесс любого пользователя, поэтому ждать можно и установщик, поднятый
под другой учётной записью администратора. Запуск идёт независимо от кода
выхода установщика: при отмене Inno Setup откатывает файлы, и прежняя версия
остаётся рабочей. `tenga-proxy.iss` не меняется: `postinstall skipifsilent`
в тихом режиме и так пропускается.

## Части

1. `src/core/app_update.py`: `AppRelease` получает `asset_url`, `asset_size`,
   `asset_digest` из `browser_download_url`, `size`, `digest` подходящего
   ассета. Ссылка на файл принимается только вида
   `https://github.com/vebulogmetra/tenga-proxy/releases/download/<tag>/<имя>`,
   где `<tag>` — тег релиза, `<имя>` — имя ассета из безопасных символов;
   digest — `sha256:` и 64 hex. Конфиг хранит три поля рядом с `app_update_url`.
2. `src/core/app_installer.py` (без тулкита и ОС): `download_installer` —
   потоковая загрузка в `%TEMP%\veblock-update\` через локальный прокси, если
   он есть, иначе напрямую; перенаправления только по HTTPS; чтение не дальше
   `asset_size`; сверка размера и SHA-256; удаление файла при ошибке;
   `verify_installer` — та же сверка по готовому файлу; `remove_stale_downloads`
   — очистка каталога при старте (`gui.py`, рядом с `cleanup_legacy_install`).
   Здесь же исключения `InstallerDownloadError`, `InstallerCorruptError`,
   `InstallCancelled`.
3. Фасад `src/sys/app_install.py`: `can_self_update()` и `launch_installer(path)`.
   `src/sys/windows/app_install.py` — `ShellExecuteExW` с `runas` и
   `SEE_MASK_NOCLOSEPROCESS`, отказ в UAC (код 1223) → `InstallCancelled`, затем
   наблюдатель перезапуска; `can_self_update()` истинно только в собранном
   приложении (`sys.frozen`). `src/sys/linux/app_install.py` — `False` и
   `NotImplementedError`. Виджеты спрашивают контроллер, `IS_WINDOWS` не
   читают; `--ui qt` на Linux сохраняет «Открыть релиз», GTK не меняется.
4. `AppController.install_app_update()`: проверка, подтверждение, фоновая
   загрузка с прогрессом, отключение через `disconnect_proxy(then=...)`,
   повторная сверка и запуск в фоне, `Shell.quit()`. Состояние —
   `app_update_status` (текст и признак занятости), интерфейс получает
   `Shell.refresh_app_update()` и читает его. Ошибки идут и в подпись, и
   тостом: установку могли начать из тоста при закрытых настройках.
5. Действие `install-app-update` в обоих интерфейсах; Qt-страница «О программе»
   показывает «Обновить…» или «Открыть релиз» по `can_self_update()`.

## Ошибки

- Нет установщика или `digest`: кнопка неактивна, подпись «Установщик
  недоступен, обновите вручную со страницы проекта».
- Сеть или прокси: «Не удалось скачать обновление», файл удаляется.
- Несовпадение размера или хеша: «Файл повреждён, попробуйте позже», запуска нет.
- Отказ в UAC: «Установка отменена», приложение работает дальше.
- Установщик не запустился по другой причине: «Не удалось запустить установщик».
- Повторный запуск во время загрузки невозможен: действие и кнопка неактивны.

## Безопасность

- Ссылка на файл — только из ответа API, хост и путь проверены; перенаправления
  только по HTTPS.
- Целостность — `digest` из того же ответа по TLS. Подписи Authenticode нет:
  доверие к GitHub то же, что при ручной загрузке.
- Уникальное имя во временном каталоге пользователя; хеш сверяется ещё раз
  непосредственно перед запуском.
- Служба не участвует, её pipe не расширяется. Тихая установка через службу
  отвергнута: без проверки подписи это запуск произвольного exe от SYSTEM.
- Наблюдатель получает PID и путь к exe аргументами, скрипт собирается из
  констант и экранированного пути.

## Тесты

- `tests/test_core_app_update.py`: поля ассета, отказ для чужих хостов, путей и
  тегов, без digest.
- `tests/test_core_app_installer.py`: loopback-сервер, прогресс, прокси и
  обход, перенаправление на HTTP, несовпадения, предел, очистка.
- `tests/test_sys_windows_app_install.py`: подменённый `runas`, аргументы
  установщика, код 1223, команда наблюдателя, `can_self_update()` без `frozen`.
- `tests/test_ui_controller.py`: порядок шагов, подтверждение, ошибки в
  подписи и тосте, отключение перед запуском, выход после запуска, кнопка тоста.
- `make test-qt`: кнопка по `can_self_update()`, состояния подписи, действие.
- `tests/test_sys_facades.py`: `app_install` в списке фасадов.
- `tests/test_gui_entrypoint.py`: очистка каталога загрузок при старте.

Обновление поверх живой версии проверяется вручную на Windows.
