# Самообновление на Windows

## Задача

Сейчас приложение раз в сутки находит новый релиз (`src/core/app_update.py`),
показывает тост и в «О программе» открывает страницу релиза в браузере. Дальше
пользователь сам скачивает и запускает установщик. На Windows приложение должно
скачать, проверить и запустить установщик само. Linux пока не меняется.

## Поведение

- Тост ежедневной проверки: «Доступна версия X» с кнопкой «Обновить»
  (действие `install-app-update`).
- «О программе»: кнопка «Обновить…» вместо «Открыть релиз». Активна, когда в
  релизе есть установщик Windows с контрольной суммой.
- Подтверждение: «Будет установлена версия X. Подключение прервётся, приложение
  перезапустится».
- Загрузка с прогрессом в подписи («Загрузка… 42 %»), затем проверка размера и
  SHA-256.
- Запуск установщика с UAC. Согласие — приложение штатно отключается (системный
  прокси, TUN через службу) и выходит. Отказ — остаётся работать, подпись
  «Установка отменена».
- Установщик идёт с `/SILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS
  /RELAUNCH=1` и в конце запускает новую версию от имени пользователя.

## Части

1. `src/core/app_update.py`: `AppRelease` получает `asset_url`, `asset_size`,
   `asset_digest` из `browser_download_url`, `size`, `digest`. Ссылка на файл
   проверяется строго: `https://github.com/vebulogmetra/tenga-proxy/releases/download/<tag>/<имя>`.
   Конфиг хранит их рядом с `app_update_url`.
2. `src/core/app_installer.py` (без тулкита): `download_installer` — потоковая
   загрузка в `%TEMP%\veblock-update\` через тот же прокси, что и проверка;
   предел размера, сверка с `asset_size` и `digest`, удаление при ошибке;
   очистка старых файлов при старте.
3. Фасад `src/sys/app_install.py`: `can_self_update()` и `launch_installer(path)`.
   Windows (`src/sys/windows/app_installer.py`) — `ShellExecuteExW` с `runas`,
   отказ в UAC — код 1223. Linux — `can_self_update() is False`. Виджеты
   спрашивают фасад, `IS_WINDOWS` не читают; `--ui qt` на Linux сохраняет
   «Открыть релиз», GTK не меняется.
4. `AppController.install_app_update()`: подтверждение, фоновая загрузка,
   повторная сверка хеша, запуск, выход.
5. `packaging/windows/tenga-proxy.iss`: в `[Run]` запуск без `skipifsilent` с
   `Check:` по параметру `/RELAUNCH=1`; ручная установка ведёт себя как прежде.

## Ошибки

- Нет установщика или `digest`: кнопка неактивна, подпись «Установщик
  недоступен, обновите вручную со страницы проекта».
- Сеть или прокси: «Не удалось скачать обновление», файл удаляется.
- Несовпадение размера или хеша: «Файл повреждён, попробуйте позже», запуска нет.
- Отказ в UAC: «Установка отменена», приложение работает дальше.
- Повторный запуск во время загрузки невозможен: кнопка неактивна.

## Безопасность

- Ссылка на файл — только из ответа API, хост и путь проверены; перенаправления
  только по HTTPS.
- Целостность — `digest` из того же ответа по TLS. Подписи Authenticode нет:
  доверие к GitHub то же, что при ручной загрузке.
- Уникальное имя во временном каталоге пользователя, хеш сверяется ещё раз
  непосредственно перед запуском.
- Служба не участвует, её pipe не расширяется. Тихая установка через службу
  отвергнута: без проверки подписи это запуск произвольного exe от SYSTEM.

## Тесты

- `tests/test_app_update.py`: поля файла, отказ для чужих хостов и путей, без digest.
- `tests/test_app_installer.py`: loopback-сервер, прогресс, несовпадения, предел,
  очистка.
- Запуск Windows: подменённый `ShellExecuteExW`, аргументы, код 1223.
- `tests/test_ui_controller.py`: порядок шагов, ошибки в подписи, кнопка тоста.
- `make test-qt`: кнопка по `can_self_update()`, состояния подписи.
- Тест `.iss`: запуск по `/RELAUNCH`, прежний `postinstall` на месте.
- `tests/test_sys_facades.py` сверяет сигнатуры фасада.

Обновление поверх живой версии проверяется вручную на Windows.
