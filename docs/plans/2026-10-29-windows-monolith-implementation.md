# План: «Монолит в центре» для Windows

Статус: реализация выполнена; результаты проверки ниже.
База: `87b795a` в `develop`.
Дизайн: `2026-10-29-windows-ux-design.md`, основной вариант выбран пользователем.

## 1. Область и результат

Основной экран Windows: системный заголовок, настройки и меню; центральный
монолит с состоянием, сервером и кнопкой; инструменты списка над таблицей;
сведения выбранного профиля и вход в диагностику снизу.

В низком окне верхняя область автоматически становится компактной:
состояние слева, монолит по центру, действие справа. Пользовательского
переключателя дизайна нет. Оба варианта должны иметь одинаковое поведение.

Разрешённые изменения:

- `src/ui/qt/widgets/status_card.py`, `window.py`, `models.py`, `style.qss`;
- при необходимости `src/ui/qt/application.py` для доставки UI-событий;
- новые небольшие модули только в `src/ui/qt/`, например `view_state.py`
  и `widgets/monitoring.py`;
- Qt-тесты, документация; Windows-only ресурсы и packaging — только если
  потребуются новые изображения или изменения их включения.

Без изменений: GTK, `src/ui/logic/`, общий AppController, core, хранилища,
системные фасады, служба, зависимости, Linux CI и deb-сборка.
Не менять версию и не выпускать релиз автоматически.
Экспериментальный `--ui qt` использует те же виджеты, штатный Linux — GTK.

## 2. Этап A: согласованное состояние Qt-интерфейса

Сначала отделить данные представления от раскладки. Определить одно Qt-only
состояние, которое получает существующие данные: активный профиль,
выделенный профиль, последний использованный профиль, занятость операции,
ошибку и результаты мониторинга. Бизнес-логику подключения не дублировать.

Правила:

- Без соединения цель главного действия — выбранный профиль, иначе последний
  использованный: тот же порядок, что у `connect_selected()`.
- Если профилей нет, показать действие добавления и объяснение. Монолит
  и кнопка подключения отключены, добавление доступно рядом.
- При активной сессии сверху показывается её профиль. Выделение другой
  строки не меняет верхнее имя и не вызывает подключение.
- «Подключено» означает запущенную сессию; результат проверки сети выводится
  отдельно. Не выводить «Защищено» или успешную проверку без данных монитора.
- Использовать `started_mode`, а не ещё не применённые настройки режима.
- Во время подключения и отключения главные элементы заблокированы;
  показываются «Подключение…»/«Отключение…». Отмену не изображать:
  существующий контроллер не умеет отменять незавершённое подключение.
- Сохранить краткую ошибку в Qt-представлении до новой попытки либо
  достоверного изменения состояния. Обычное обновление списка или монитора
  не должно сразу заменять её на «Отключено».
- Если переключение не удалось, но прежняя сессия ещё работает, показывать
  фактический активный профиль и отдельное сообщение об ошибке переключения.

Учесть все точки запуска: главная кнопка, монолит, меню строки, Enter,
двойной клик и существующие действия приложения. В Qt-оболочке обеспечить
немедленное обновление занятости после отправки действия; не добавлять
новые потоки подключения или опрос ради анимации.

Критерий: один набор данных управляет подписями, доступностью и целью
клика монолита и текстовой кнопки во всех состояниях.

## 3. Этап B: центральная карточка и кликабельный монолит

- Заменить QLabel логотипа на настоящую Qt-кнопку с изображением.
- Монолит и текстовая кнопка испускают один `action_clicked`, связанный
  с существующим `toggle-connection`. Не вызывать сервис из виджета.
- Сохранить текстовую кнопку: «Подключить», «Отключить», «Повторить».
- Дать монолиту доступное имя текущего действия, tooltip, фокус, Space/Enter,
  hover/pressed/disabled-состояния. Не назначать второй конфликтующий shortcut.
- Начальный размер изображения 108 логических пикселей; цель нажатия
  около 120. Уточнить по нативным снимкам, не растягивать пропорции.
- Проверить качество исходного ресурса при 200% DPI. Использовать имеющийся
  вектор/исходник, если доступен; новые изображения — только Windows-only.
- Под логотипом: состояние, имя сервера с флагом, режим и небольшая строка
  показателей. Длинные названия сокращаются с полной подсказкой.
- Имя и состояние остаются в стабильных местах при обновлении трафика.
- Спокойный интерфейс: один акцент подключения, без постоянного свечения
  и пульсации. Цвет дополнен текстом, рамка фокуса видна в обеих темах.

Начальные ориентиры высоты: 220–280 для центрального представления,
130–160 для компактного. Порог считать по доступной области клиента и
минимально полезной высоте списка, а не по физическим пикселям монитора.
Добавить небольшой гистерезис порога, чтобы раскладка не переключалась
туда-обратно при изменении minimum size или появлении сообщений.
После выбора раскладки монолит центрируется по ширине основной области.

## 4. Этап C: инструменты списка и разделение профилей

- Вынести настройки и меню из карточки в верхнюю служебную строку.
  Использовать существующие QActions, не создавать вторые обработчики.
- Поиск и меню «Добавить…» разместить непосредственно над списком.
  Ctrl+F и очистка поиска сохраняются.
- У активного профиля — явная текстовая метка «Подключён», отдельная
  от фона выделения. Полужирное начертание может дополнять метку.
- Под списком — имя выбранного профиля и краткие сведения.
- Если активный и выбранный различаются, показать явное действие
  «Переключить на выбранный» с именем цели. Оно вызывает существующее
  `connect-profile` с id выбранной строки, а не toggle отключения.
- Пока выбран активный профиль, лишнюю кнопку переключения скрыть.
- Enter/двойной клик сохраняют прежний путь активации профиля.
- Сохранить раскрытие групп, выделение по id и позицию чтения при
  обновлении модели, поиске, сортировке и пакетном замере.
- Не менять порядок строк автоматически при каждом результате замера.
- Колонку адреса в этой итерации сохранить: её удаление не согласовано.
  Подсказки адресов, типы протоколов, пинг и сведения подписок остаются.
- Пустой список и отсутствие результатов показывать внутри области
  содержимого; добавление и очистка фильтра остаются доступными.

Критерий: одинарный клик и навигация стрелками не меняют соединение;
подключение выбранного профиля всегда требует явной активации.

## 5. Этап D: диагностика по запросу

- Убрать постоянную правую колонку, освободив ширину списка.
- Добавить снизу кнопку раскрытия «Диагностика» и краткую строку состояния.
- Мониторинг разместить в сворачиваемой области под списком; журнал
  сохранить в отдельном немодальном окне, доступном из диагностики и меню.
- Для ширины/высоты, где раскрытая область делает список непригодным,
  открыть те же показатели в отдельном немодальном Qt-окне.
- Сохранить «Проверить сейчас», время последней проверки, DIRECT/PROXY/VPN
  и реальные сообщения ошибок. Не смешивать их с пакетным пингом профилей.
- Использовать существующее предпочтение `monitoring_panel` для видимости
  мониторинга, без изменения общей схемы и значений по умолчанию.
- Не пересоздавать показатели целиком на каждом обновлении, если достаточно
  обновить текст. Это сохраняет фокус и снижает визуальное мерцание.
- Скрытый журнал не читает файлы по таймеру. Закрытие/скрытие основного окна
  корректно обслуживает вспомогательные окна, повторное открытие не создаёт
  дублирующих таймеров или окон.

## 6. Этап E: целевые и регрессионные проверки

Добавить тесты по мере реализации, затем выполнить Qt-набор целиком:

- оба элемента карточки отправляют ровно одно одинаковое действие;
- недоступные элементы не вызывают действие, во время операции нет
  повторного запуска и ложной отмены;
- доступное имя и подпись согласованы с состоянием;
- выбранный/последний/активный профиль корректно отображаются и используются;
- ошибка не исчезает при постороннем refresh;
- выделение другого сервера не переподключает; явное переключение адресует
  правильный id; отказ не скрывает реально оставшуюся активную сессию;
- активная метка независима от выделения, контекстные меню и shortcut работают;
- раскрытие диагностики, fallback в отдельное окно и жизненный цикл журнала;
- сохранение выделения, свёрнутых групп и прокрутки при обновлениях;
- геометрия центрального/компактного режимов, длинные строки и пустые состояния.

Данные синтетические, конфигурация в tmp_path, сеть, процессы и системные
операции подменяются. Пользовательские профили не использовать.

Выполнить обязательный Windows unit-набор из AGENTS.md, Ruff check,
проверку форматирования и git diff --check. Целевые тесты должны запускаться
в обычном CI offscreen; нативную проверку Windows провести отдельно.

## 7. Этап F: нативная проверка и сборка

- Снимки до/после: обычное и низкое окно, развёрнутое окно, обе темы,
  состояния отключения/запуска/подключения/ошибки и разные выбранный/активный.
- DPI 100%, 125%, 150%, 200%; переход между мониторами — если доступен.
  Эмуляцию QT_SCALE_FACTOR не выдавать за физическую смену DPI.
- Проверить Tab, Space, Enter, Ctrl+F, контекстное меню и видимость фокуса.
- Убедиться, что центральная область не вытесняет список за пределы окна,
  а минимальная геометрия укладывается в доступную рабочую область.
- Собрать штатным `core/scripts/build_windows.sh` с очищенным PATH:
  не подхватывать ICU из bundled Poppler окружения Codex.
- Frozen smoke с отдельными пустыми настройками: процесс жив, Qt выбран,
  QSS и Windows-ресурсы включены, GTK и traceback отсутствуют.
- Собрать Inno Setup, записать версию, размер и SHA-256. Не устанавливать
  приложение и службу ради smoke без отдельной необходимости.
- Сверить итоговый список изменённых путей с разрешённой областью.

Linux GTK, D-Bus, TUN и deb на Windows не проверяются и не объявляются
прошедшими. Недоступную Windows 10 или смену мониторов перечислить в отчёте.

результаты и ограничения, а не только скриншот HTML-концепции.

## 10. Первая реализация до последующих замечаний

- Центральный кликабельный монолит и текстовая кнопка используют один
  action; доступны Space/Enter и видимый фокус. Во время операции оба
  элемента недоступны, ложная отмена убрана.
- Для DPI добавлен векторный ресурс `assets/icons/win/monolith.svg`;
  его использует только Qt-фронтенд. Прежние ресурсы не удалены.
- Qt-only `ConnectionPresentation` сохраняет ошибку между обновлениями,
  различает подключение/отключение и оставшуюся рабочую сессию при отказе.
- Активный сервер отмечен независимо от выделения; переключение на другой
  профиль выполняется отдельным действием. Колонка адреса сохранена.
- Поиск и добавление над таблицей, настройки доступны напрямую.
- Центральная и компактная компоновки автоматически переключаются с
  гистерезисом 720/780 логических пикселей высоты клиента. При встроенной
  диагностике карточка компактная, чтобы сохранить место списку.
- Диагностика встроена снизу при достаточном месте; ниже 760 по высоте
  или 1050 по ширине используется отдельное немодальное окно. Журнал
  остаётся отдельным окном с прежними экспортом и маскированием.
- Последняя проверка предыдущей сессии не выдаётся за проверку новой.
- Обновления трафика/монитора не пересоздают дерево. При пересборке
  сохраняются выделение, группы и прокрутка; во время замера строки
  не пересортировываются с каждым результатом.

Проверки: полный Qt-набор offscreen и полный нативный Qt-набор — по 165 passed;
последние изменения
подтверждены целевым набором — 18 passed. Windows unit-набор —

Четыре масштаба Qt × две темы × три размера — 24 passed.
Ruff check, format --check и git diff --check прошли.

Нативные снимки состояний, обеих тем, компактной карточки, встроенной и

Для ошибки имя сервера и причина разделены, текст ошибки не дублируется.

## 11. Правки по замечаниям пользователя

Эта секция заменяет решения первой итерации, где они расходятся:

- Отдельная кнопка подключения полностью удалена. Остались кликабельный
  монолит и подпись «Нажмите на логотип для подключения», меняющаяся
  для отключения, повторной попытки и занятого состояния.
- Дублирующая строка «Выберите сервер и подключитесь» убрана. Сообщения
  ошибки и результата проверки сохраняются, пустая строка не занимает место.
- Для новых Qt-настроек и старых файлов без поля темы используется светлая
  тема. Явно сохранённые light/dark/system не сбрасываются. Общий default
  DataStore и Linux не меняются; реальные настройки напрямую не редактируются.
- «Меню» использует QPushButton, как «Настройки»: высоты совпадают, стрелка
  расположена справа. «О программе» удалено из меню, раздел остаётся
  в настройках. Другие точки входа и действия не удалены.
- В строке группы во время замера рисуется горизонтальный progress bar
  из пары done/total, одновременно доступен текстовый счётчик. Дополнительная
  высота относится только к группе, после завершения/сброса полоса исчезает.
  Индивидуальные QWidget на строки не создаются.
- В обслуживании подписи, описания и кнопки выровнены по вертикали,
  кнопкам очистки и обновления заданы одинаковые минимальные ширины.
