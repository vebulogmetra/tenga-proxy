# Запасной адрес подписки: разовая загрузка

Перенос с Android (`tenga-proxy-android`, коммит `57e0f1ee`, `docs/subscriptions/`) на десктоп:
GTK и Qt работают через общий `AppController`.

## Что уже есть

`fallback-url` разбирается (`src/sub/metadata.py`) и хранится в `ProfileGroup.sub_fallback_url`.
После неудачного обновления `AppController` предлагает диалог «Сменить адрес подписки?».

## Что добавляется

Если основной адрес не ответил, подписка один раз загружается с запасного. `subscription_url` не
меняется, следующее обновление снова начинается с основного. Постоянная смена адреса — по-прежнему
только с подтверждения пользователя (`src/sub/url_change.py`).

## Когда пробовать запасной адрес

| Результат основного адреса | Запасной |
|---|---|
| Сетевая ошибка после всех попыток и маршрутов | да |
| HTTP 5xx, 403, 429 | да |
| HTTP 404, 410 и прочие коды | нет |
| HTTP 200, в том числе пустой список | нет |
| Ответ больше `MAX_RESPONSE_SIZE` | нет |
| `SubscriptionPolicyError` | нет |

403 и 429 может отвечать сам CDN. 404 и 410 означают отозванный токен: запасной адрес несёт тот же
токен и ответит так же.

## Загрузка

`src/sub/fallback.py` — чистые функции и исключение, как `SubscriptionFallback.kt`:

- `is_worth_trying(error)` — таблица выше;
- `usable_url(primary, stored)` — запасной адрес или `None`. Проверяется при каждой загрузке:
  значение из файла профилей не считается доверенным. Адрес, равный основному по нормализованному
  ключу, не запрашивается: панель отдаёт второй адрес всегда, и после перехода на него они совпадают;
- `display_error(primary, fallback)` — ответ сервера объясняет отказ лучше, чем обрыв связи;
- `can_propose_after(error)` — нужен ли диалог смены адреса после ошибки;
- `FallbackExhaustedError(display_error)` — не сработали оба адреса.

`SubscriptionUpdater.update()` при сбое основного адреса вызывает `fetch_response` для запасного и
обрабатывает ответ обычным путём. Адрес, с которого реально загружено, лежит в
`updater.used_fallback_url`, рядом с `new_url`. Заголовки те же, включая HWID, если он включён:
запасной адрес указал тот же провайдер, и второе устройство на панели не появится.

Нормализация адреса выносится из `find_subscription_group` в `subscription_url_key()` на уровне
модуля `src/db/profiles.py`.

## Данные

`ProfileGroup.sub_via_fallback: bool` — последнее успешное обновление пришло с запасного адреса.
Хранится в JSON со значением по умолчанию, миграция не нужна. Ошибка флаг не меняет.

`sub_fallback_url`:

- новое приемлемое значение сохраняется из любого ответа;
- стирается только ответом основного адреса, в котором есть серверы и нет приемлемого значения.
  Ответ без серверов не стирает: страница CDN с кодом 200 разбирается как пустой список и убрала бы
  запасной адрес именно при сбое CDN. Ответ запасного адреса тоже не стирает.

**Отличие от Android:** при смене адреса в `AppController.update_group` `sub_fallback_url` и флаг
сбрасываются. Иначе после перехода к другому провайдеру сбой нового адреса молча подтянул бы серверы
старого, с его токеном.

## Что видит пользователь

| Итог обновления | Результат |
|---|---|
| Успех с основного адреса | Как сейчас: диалог, если пришёл `new-url` |
| Успех через запасной | Тост «Обновлено серверов: N» и диалог смены адреса. Если есть и `new-url`, сначала предлагается он: очередь показывает одно предложение за раз |
| Упали оба адреса | Обычная ошибка, диалога нет |
| 404 или 410 | Ошибка, диалога нет |
| Другая ошибка, запасной не пробовали | Ошибка и диалог, как сейчас |

**Отличие от Android:** там после успеха через запасной адрес диалога нет, предложение ждёт за
бейджем на карточке. У десктопа нет отложенных предложений, а подписки обновляются только по
действию пользователя, поэтому диалог не появится неожиданно. Он будет возникать при каждом
обновлении, пока основной адрес не работает.

Причина `REASON_FALLBACK_USED` и текст: «Основной адрес подписки «X» не ответил, серверы загружены с
запасного. Перейти на него насовсем?».

В строке подписки — приглушённая подпись «Обновлено через запасной адрес»
(`SubscriptionRow.via_fallback`): страница подписок GTK и настройки Qt.

## Что не переносится

Параллельное обновление и бюджет времени из `SubscriptionAutoUpdateWorker`: фонового обновления на
десктопе нет. Цена: «Обновить подписки» идёт последовательно, и мёртвая подписка с запасным адресом
задержит остальные примерно на 6 минут в худшем случае (3 попытки по 30 с, два маршрута, два адреса).
