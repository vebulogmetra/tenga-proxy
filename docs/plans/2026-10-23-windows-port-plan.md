## Цель по фазам

| Фаза | Итог |

## Общие правила для всех фаз

- TDD: сначала падающий тест, потом код. Один логический коммит на задачу,
  сообщения коммитов на русском в стиле репозитория (`feat(sys): …`).
- Исправление поведения и рефакторинг — разными коммитами.
- **Windows-модули импортируются на Linux.** `winreg`, `ctypes.windll`,
  `win32*` импортируются лениво, внутри функций, либо через внедряемый объект.
  Тогда вся логика (разбор вывода, сборка команд, протокол, политика,
  журнал) тестируется обычным `uv run pytest` на машине разработчика.
- Тесты, которым нужна настоящая Windows, помечаются маркером `windows` и
  на Linux пропускаются (маркер заводится в задаче 1.1).
- Linux-поведение не меняется. Перед каждым коммитом — полный
  `uv run pytest` и `python cli.py lint-all`.
- **Не запускать xray с TUN-конфигами на машине разработчика:** интерфейс
  `xray0` занят рабочим подключением. TUN проверяется в CI на Windows и на VM.
- Что не удалось проверить на Windows, записывается в раздел «Статус» плана
  фазы, а не замалчивается.

## Кто что проверяет

- **Исполнитель (Claude на Linux):** код, unit-тесты, lint, сборка проходит в CI.
- **CI `windows-latest`** (с фазы 2): тесты с маркером `windows`, сборка
  установщика, с фазы 3 — интеграционный тест службы.
- **Владелец проекта на Windows VM:** задача 1.0 (разведка) и ручная приёмка в
  конце каждой фазы. Чек-листы приёмки — последние задачи планов.

## Окружение разработки на Windows

Используется MSYS2 UCRT64, не `uv`: PyGObject и GTK берутся из пакетов MSYS2,
pip их не соберёт. Так же собирает Windows-версию Gaphor (GTK4 + libadwaita +
PyInstaller), его сборку можно использовать как образец.

```bash
# В оболочке «MSYS2 UCRT64»
pacman -S --needed git unzip \
  mingw-w64-ucrt-x86_64-python mingw-w64-ucrt-x86_64-python-pip \
  mingw-w64-ucrt-x86_64-python-gobject mingw-w64-ucrt-x86_64-gtk4 \
  mingw-w64-ucrt-x86_64-libadwaita mingw-w64-ucrt-x86_64-python-requests \
  mingw-w64-ucrt-x86_64-python-pytest mingw-w64-ucrt-x86_64-python-pytest-cov \
  mingw-w64-ucrt-x86_64-python-pywin32
python -m venv --system-site-packages .venv-win
. .venv-win/bin/activate
pip install pyinstaller
bash core/scripts/install_dev.sh    # xray.exe, wintun.dll, геобазы (задача 1.12)
python gui.py
```

Задача 1.0 подтверждает, что эти пакеты существуют и работают; если какой-то
пакет называется иначе, его имя исправляется здесь и в CI.

## Риски

| Риск | Где проверяется | Запасной вариант |
|---|---|---|
| xray не поддерживает unix-сокет статистики на Windows | 1.0 | Сокет на `127.0.0.1` со случайным портом, только для GUI-процесса |
| `sockopt.interface` не работает на Windows или ждёт не то имя | 1.0 | Только host-маршрут до прокси, без привязки; в VPN-режимах — маршрут через VPN-адаптер |
| В MSYS2 нет `python-pywin32` | 1.0 | `pip install pywin32` в venv; если не ставится — служба на ctypes (отдельное дополнение к фазе 3) |
| PyInstaller не собирает GTK4 из MSYS2 | 2.4 | Сверка со сборкой Gaphor; крайний вариант — поставка дерева MSYS2 без PyInstaller |
| `Shell_NotifyIcon` из второго потока конфликтует с GTK | 2.3 | Окно трея в главном потоке и опрос сообщений через `GLib.timeout_add` |
