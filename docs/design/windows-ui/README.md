## Реализованное поведение

- Постоянная панель подключения слева; серверы и диагностика справа.
- Крупный монолит активируется мышью, Space и Enter. Во время операции он
  недоступен. Бирюзовое свечение означает запущенную сессию; результат проверки
  доступности выводится отдельной строкой. Оранжевое означает операцию, красное —
  ошибку или блокировку. В отключённом состоянии свечения нет.
- Двухстрочные серверы: имя, протокол и адрес, задержка и меню. Бирюзовый маркер
  и подпись активного сервера сохраняются при выделении другой строки.
  Системное выделение и рамка фокуса показывают выбранную строку. Выбор не
  переключает сессию; явное действие находится под списком рядом с именем цели.
- Меню сортировки сохраняет существующие ключи и переключает направление
  повторным выбором того же ключа. Контекстное меню доступно также справа в строке.
- Диагностика содержит сводку, маршрутизацию и единственный журнал. Возврат
  сохраняет модель, выделение, запрос и прокрутку. Ctrl+F возвращает к поиску.
  Таймер журнала работает только на видимой странице видимого окна; чтение,
  экспорт и очистка выполняются в фоне, очистка требует подтверждения.
- Старое поле `monitoring_panel` не удаляется и не меняется при переходах Qt.
  При запуске всегда открываются серверы; отдельное окно автоматически не возникает.
- Настройки сохраняют шесть разделов, автоматическое сохранение с задержкой
  500 мс, проверку полей и сброс задержки при закрытии. Ожидание, ошибка проверки,
  ошибка записи и успешная запись различаются. Успех подтверждается контроллером.
  Параметры TUN скрываются для системного прокси без потери значений. Проверка
  доступа TUN показывает ожидание, результат или ошибку. Изменения рабочей сессии
  требуют явного переподключения; выбранная тема применяется сразу.

## Воспроизведение визуальной проверки

Из корня репозитория, с установленными зависимостями разработки и PySide6:

```powershell
$env:QT_QPA_PLATFORM = "windows"
python -m tests.support.render_windows_ui .test-tmp/visual
```

Сценарий создаёт только синтетические серверы и журнал во временном каталоге,
использует подменённую службу подключения, не устанавливает системный прокси
и не запускает TUN. `--interactive` оставляет демонстрационное окно для проверки
системной рамки и клавиатуры. Без этого флага окна рендерятся скрыто, чтобы
физический размер монитора не ограничивал логические размеры при высоком DPI.

Снимки проверены для 900×540 и 1180×760, светлой, тёмной и системной тем,
итогового DPR 1, 1.5 и 2. На машине с базовым DPI 125% для этих прогонов
использованы `QT_SCALE_FACTOR=0.8`, `1.2`, `1.6`; на другой машине множители
нужно пересчитать относительно её базового DPI. Компоновка использует логические
пиксели, а SVG кэшируется по размеру, DPR и состоянию. Скриншоты состояний сняты
отдельно от реальных сетевых операций.

Обычным запуском на Windows дополнительно проверены системная рамка,
разворачивание, Ctrl+F, поиск без результатов и переходы серверы/диагностика.
Инструменты: Qt Windows backend и навык computer-use.

## Ограничения среды

Linux GTK, D-Bus, TUN, deb-сборка и полный Linux-прогон с покрытием здесь
не выполнялись. Реальные подключения через установленную Windows-службу,
восстановление сети и ручная проверка Snap Layouts и трея остаются для приёмки
в окружении с настроенной службой. Тесты интерфейса используют подмены.
Масштабирование проверено через Qt DPR, настройки масштаба самой ОС не менялись.
Для обычного окна 1180×760 при 150/200% текущего физического экрана недостаточно:
полная компоновка проверена скрытым рендером Windows-бэкенда.
